# Flujo de colaboración

## Ramas

- `docs/<tema>` para especificaciones y documentación.
- `feature/<tema>` para funcionalidad.
- `fix/<tema>` para correcciones.
- `test/<tema>` para pruebas independientes.
- `chore/<tema>` para configuración y mantenimiento.

## Commits

Usar mensajes breves y comprobables, por ejemplo:

- `docs: definir resultados odd iniciales`
- `feat: validar conflictos de reserva`
- `test: cubrir doble reserva de una cancha`

## Pull Requests

- Relacionar un Issue.
- Explicar qué cambia y por qué.
- Identificar requisitos y criterios afectados.
- Incluir pruebas ejecutadas.
- Evitar mezclar cambios no relacionados.

No se integran cambios funcionales con pruebas fallidas.
